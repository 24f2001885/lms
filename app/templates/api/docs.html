API reference

Base path /api/v1. JSON in, JSON out. Sign in through the normal login page; the session cookie is the credential.

Authentication

All /api/v1 endpoints (except this documentation page) authenticate using the standard Flask session cookie established via POST /login.

  • Call GET /api/v1/session to verify your active session and retrieve csrf_token.
  • Send X-CSRFToken: <token> and Content-Type: application/json on every POST, PUT, and DELETE request.

Conventions

  • Timestamps: All dates and times use ISO 8601 UTC format ending in Z (e.g., 2030-01-10T04:30:00Z). Input timestamps without a timezone offset or Z are rejected with 422.
  • Pagination: List endpoints accept page (default 1) and per_page (default 20, maximum 100) and return {"items": [...], "page": 1, "per_page": 20, "total": 42}.

Errors

Every error response uses the uniform JSON shape:

{
  "error": {
    "code": "validation_error",
    "message": "Some fields are invalid.",
    "fields": {
      "slot_id": ["This field is required."]
    }
  }
}

Quick curl example

# 1. Fetch CSRF token using an active session cookie jar
CSRF=$(curl -s -b cookies.txt /api/v1/session | python3 -c "import sys,json; print(json.load(sys.stdin)['csrf_token'])")

# 2. Book a slot
curl -s -b cookies.txt -X POST /api/v1/bookings \
  -H "Content-Type: application/json" \
  -H "X-CSRFToken: ${CSRF}" \
  -d '{"slot_id": 2}'

Intentionally Absent Endpoints

Booking rescheduling (ADM-16), examiner approval, and temporary password generation remain HTML-only administrative actions in Tier 2; there is no PUT /api/v1/bookings/<id> or write endpoints under /api/v1/examiners and /api/v1/students.
